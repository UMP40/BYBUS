# 零协持久汉化启动器

本地版本基于 BBBEANNN/limbusZhCN 提交 `997dde5e0a1fadec9f18ded852d7f285ea613b66`，面向未 Root 的 arm64 手机。目标验证设备是 vivo X100 Ultra / OriginOS 6 / Android 16；构建检查不能代替真机启动、资源下载和账号登录验证。

## 用户流程与保存边界

- 打开启动器即检测 `com.ProjectMoon.LimbusCompany`；首次点击启动自动导入系统已安装的 base / split APK。后续检测游戏版本和安装来源变化，必要时同步，保留容器数据。
- 容器使用独立数据目录，不迁移原版游戏的私有登录状态和已下载资源。首次需要在容器内重新登录、下载游戏资源，并额外占用相应空间；这里的“保留数据”指容器里已经产生的数据。
- 普通启动固定查询都市零协会（LocalizeLimbusCompany）公开 GitHub 最新正式 Release。保留原始 HTTPS 下载与 SHA-256 校验，不提供替代源或 Token 设置。
- 汉化包、解压资源、索引和当前激活指针均保存在应用 `filesDir` 下。不会因关闭应用、重启手机或系统清理缓存而主动删除；卸载、清除应用数据仍会删除它们。
- 每次启动都先尝试联网检查并校验本地包。已有索引有效而联网失败时，提示使用上次版本。首次尚无有效索引时不能把下载成功误报为汉化已生效。
- 索引清单包含二进制 SHA-256；离线复用前校验指针位置、文件存在和哈希。重新编译发现同代文件损坏或缺失时原子修复，不把损坏索引标记为可用。
- 游戏日文资源在容器内下载完成后，再从启动器启动一次编译完整索引。首次资源准备模式、已缓存汉化、已激活汉化分别展示。
- 高级设置的“重新同步游戏”只同步；实际游戏启动统一经过主按钮的更新流程。
- 启动按钮结束已有的容器游戏进程并等待其退出，再创建新的游戏进程读取当前索引；不会只恢复持有旧索引的后台页面。仅操作 Limbus 虚拟包，不清除游戏数据或停止 microG。
- 不修改系统游戏私有数据；直接点原版游戏图标不会加载容器索引。APK 不包含游戏本体或用户账号数据。
- Google Play 仍可更新原版，汉化器下次启动会检测并同步。游戏新构建可能改变底层兼容位置，需另行验证；汉化包更新不能替代汉化器的版本适配，未知构建不套用旧版本的固定位置修复。

## Android 16 与构建

应用上游提交 `964cb68a62971a7f73e8357cc40ad00d91cdc762` 的 Provider 身份修复：Android 12+ 系统 Binder 边界使用实际宿主 UID、PID、包名；虚拟 UID 仍用于容器内部。此改动不代表所有 Android 16 登录问题均已解决。

保留上游 arm64 / NDK `30.0.14904198` 配置。与游戏版本绑定的 native 操作只允许匹配经过核验的版本、系统范围、ABI、内存页大小和两个库哈希时启用。当前配置限定 Google Play 游戏 1.114.0 / 471、Android 16、arm64、4 KiB 页面和实机提取的两个库 SHA-256。已在 vivo X100 Ultra 完成 Google 登录、资源准备、中文主界面和角色/技能文本抽查，签名 Release 覆盖安装后仍能进入主界面且保留登录和资源。未知构建关闭固定位置操作，不能据此宣称通用 Android 16 兼容。交付签名 release 构建，关闭调试 Intent；私钥只保存在本地忽略目录，后续升级复用同一密钥。

验证范围：运行上游及新增相关 JVM 单元测试，生成 APK，核对签名、包信息、microG 资源 SHA-256、原生库和 16 KB 对齐。没有连接目标手机时，必须明确标记真机项目未验证。

## 界面与启动优化

### 1.5-llc.5 界面修订

首页改为克制的深色启动台：主要入口使用圆形启动控件，显示简短状态；版本、运行时回执、错误详情及维护操作移至底部面板。按钮支持按压回弹、触感反馈，启动动画对应真实准备阶段，不显示伪造百分比。横屏与紧凑屏幕分别适配，保留原有启动条件、更新检查、持久索引及诊断功能。此轮先在本地与手机预览，用户明确要求暂不上传 GitHub。

维护操作完成后以短提示反馈，完整结果保留在状态面板；首次尚未保存汉化时，主按钮下方提供使用说明入口。提示不把汉化包下载完成等同于索引激活。

2026-09-23 验证：91 项 JVM 测试及签名、资源、对齐检查通过，Release 覆盖安装保留现有汉化。实机检查首页、设置、状态和说明面板，返回键关闭面板，横屏布局可见且无裁切。用户通过新版界面进入采光页后反馈游戏内仍有漏译与字重差异；这些是后续文本渲染修复的验证目标，不以启动成功视作汉化完整。

- 首页使用石墨色、暖白与少量橙色，突出唯一的启动入口；状态与维护信息按需展开。刻度、图标和背景以 Compose 绘制，字标使用 107 KiB 的 OFL 字体，不引入图片或动画框架。
- 首页状态读取和索引校验在后台执行。任务由应用级 `LaunchCoordinator` 持有，ViewModel 仅转发状态和操作；文件锁覆盖 UI、调试入口及其他进程。关闭重开 Activity 不会创建相互覆盖的任务。
- 每次启动仍查询正式 Release；包哈希及解压文件全部通过校验才复用解压目录。日文源文件内容、汉化文件内容及索引编译规则组成指纹，指纹与有效激活索引一致才跳过 JSON 配对和编译。资源变化、文件损坏或索引失效必须重新构建。
- 包体积优化仅改变资源的无损存储编码和编译产物；内置 microG 的解码结果及签名、完整中文字体必须与原文件一致。现有安装的已展开资源继续复用。
- 完整字体在 Gradle 中生成 XZ 资源，启动游戏前由宿主后台线程解压并校验完整 SHA-256，避免阻塞游戏主线程；原字体文件名和运行时位置保持一致。microG APK 字节与资源拆分方式不变。
- Release 启用 R8 和资源裁剪；保留 VirtualApp、mirror、xdja、hidden API 和 Google/Firebase 桥接类的反射边界。四个 GMS Task compile-only 类型由游戏类加载器提供，仅对这四类抑制缺失警告。NDK 显式对齐项目版本，恢复宿主原生库符号剥离。
- 报告区分实际 APK 字节数、JVM 缓存路径测试与手机启动时间；没有设备时不宣称真机加速比例。

## 架构修复（1.5-llc.3）

同步采用不可变 APK 快照、持久修复标记及 native 库暂存替换。索引配对验证结构、稳定 ID、完整度、记录量和编译前后输入指纹；失败保留旧索引。停用只撤销索引，不改动游戏资源；旧文件恢复必须有独立所有权记录。HTTP 错误流关闭，JSON 协议按结构解析，网络和解压都有预算。

主页显示运行时确认状态；索引保存不表示游戏已进入或汉化已显示。关闭系统备份与设备迁移，缓存保留当前、上一版及本次待激活版本，旧恢复基线受保护。详细规则、回归测试和未完成的真机验证见 `architecture-hardening.md`。

# v478 兼容与文本布局修复

本页记录内部版本 38 的实测。内部版本 39 在保留旧配置的基础上增加同结构自动适配，
判定规则见 [自动兼容](automatic-native-compatibility.md)；以下固定白名单描述是当时的实现。

2026-10-05：用户升级到 1.116.1 / 478 后，被现有仅包含 471、475 的启动配置拦截。
当前任务先恢复新构建启动，再排查镜像迷宫字体、战斗左上角马蒂斯与绮罗播报及漏译。

## 兼容边界

- 新配置仍绑定版本、SDK 36、arm64、4 KiB 页和两个原生库的完整 SHA-256。未知构建继续拒绝。
- 已从设备提取官方 APK，只读核对 ELF 段布局。保护库的 JNI 清理/完整校验代码
  `0x70000..0x70f00` 与已验证版本逐字节一致；静态 maps、报告入口和清理指令亦吻合。
- 478 的原始 CRC 已由确切调用点的有界栈记录及恢复自有补丁后的完整重算相互验证，
  固定为 `b913d99f / bfb79f2d`，保护库为 `b14fa8ae`。最终配置与 471、475 一样，
  同时核对固定 CRC、模块名、完整段大小、当前 JNIEnv、原调用点和完整字节重算。
  不从错误码推断兼容，不在用户启动时学习或放宽白名单。
- 保护库自身须重算全部 179 个范围，核对完整描述表指纹、原始预期 CRC 和补丁账本。
  未登记差异、重叠补丁、当前补丁字节变化、未知范围或调用点均走原失败路径。
- 沿用稳定报告入口和完整指令校验；不把 471 的动态指令维护或 SIGILL 特判扩至 478。
- 只记录有界 CRC、范围、成功/失败等元数据。配置只有通过设备完整校验与正常启动后
  才记为实测；最终包已通过本机完整校验和启动。不会覆盖游戏 APK 或清除账号、资源。

## 文本布局边界

- 已发现短文本处理会覆盖原 overflow，显式多行短文本会被关闭自动换行。
  调整时保留游戏的滚动/分页/链接布局；保留译文换行并识别 TMP 的 br 换行。
- 当前游戏 BattleAnnouncerUI 自带描述遮罩、滚动速度、延时及异步滚动任务。
  在精确签名的 SetDescription(String) 入口先翻译，再由游戏进行测量和滚动；
  不自行模拟滚动计时，不改播报顺序或内容。必须验证方法 ABI、字段类型和入口空间。
- 播报正文保留游戏自己的布局设置。字体只在已有完整译文来源证明成立时切换；
  诊断仅记录控件角色、尺寸、字重、材质和换行数，不保存正文或账号。
- 镜像迷宫字体和未译内容须根据实际页面继续核对；资源包检查不能替代全游戏视觉验证。
- 478 元数据确认事件正文、行为说明、结果正文共用 `ChoiceScrollViewBox`，其中
  `SetTotalContent` 保存全文，`ReadingOneLineAtATime` 的字符串/字符串集合重载
  按段显示到明确的 TMP 组件。新增组件内的全文来源证明：先核对整个输入列表对应
  完整已译文本，再允许同一组件显示该全文在换行边界上的段落及逐字前缀。
  证明绑定 Unity instance ID，内容替换/清空时失效，有固定数量及长度上限；
  不将段落或任意正文子串注册为全局译文，不给其他控件授予字体身份。
  真机元数据进一步确认集合实际为 `List<ChoiceEventResultLog>`，不是字符串列表。
  只通过有界 Count/Item 反射访问确切模型的 `_resultLog: System.String` 显示字段，
  `_egoGiftID` 和判定/奖励数据不读写。同步覆盖 `ActionChoiceButton.SetButtonData`
  的按钮正文和结果说明，在原函数测量/滚动前完成文字转换及组件内来源登记。
  `TextData_ActionEvents.options` 是明确的 `TextData_DungeonEvents_Options` 集合，
  其 `message/messageDesc/result` 已属于显示白名单；补入原有有界嵌套模型遍历，
  使选项描述在游戏代入参数前翻译，而不是只在最后的 TMP 字符串上补救。
  入口须核对完整实例签名、返回类型及补丁空间；不得改用任意对象图扫描或猜测偏移。
  不改逐行协程、事件选项、判定、翻页或滚动计时。事件正文保留原布局。
- 用户停在“星之恩惠”卡片页，正文是多个说明组成的项目列表，存在字形粗细混用。
  补充有界完整列表来源证明：每个圆点项目都须完整匹配包内译文或受控参数模板；
  任意未识别项目、附加正文、未知名字均拒绝，不给子串单独授予字体身份。
- 字体诊断原来达到 32 KiB 后停止写入，导致较晚进入的页面没有记录。改为保留请求头
  与最近完整记录，仍限制每文件 32 KiB；组件采样缓存也须有界替换而非永久停止采样。
- 已在新版更新页看到未译 `DOWNLOADING UPDATE 33.22% 0/1`。仅补充这一固定状态
  及严格数字进度格式，保留百分比/数量，不泛化翻译英文正文、路径或资源键。
